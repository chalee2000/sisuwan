# AI BRIEF

แอพข่าว AI สไตล์ข่าวสาร รองรับภาษาไทยและอังกฤษ ครบ 10 หมวด: โมเดล AI, งานวิจัย, เครื่องมือ AI, AI เขียนโค้ด, ธุรกิจ AI, นโยบายและจริยธรรม, หุ่นยนต์, ชิปและฮาร์ดแวร์, AI สร้างสรรค์ และ AI ในไทย พร้อมการค้นหา บุ๊กมาร์ก และการติดตั้งเป็น PWA บนมือถือ

A responsive Thai/English AI news app with ten topic categories, search, saved articles, automatic updates, and an installable PWA shell. The app covers news **about AI**; its article excerpts come from publisher RSS feeds and are **not AI-generated summaries**.

## เริ่มต้น / Run

Use Node.js 22.12+ (Node.js 24 recommended).

```sh
npm ci
npm run dev
```

Open the Vite URL printed in the terminal (normally `http://localhost:5173`). Vite forwards `/api` requests to the Node server at `http://localhost:3001`. For the production build:

```sh
npm run build
npm start
```

Open `http://localhost:3001`. `PORT` changes the production server port. Build before starting the production server so it can serve `dist/`. For production PWA installation and service workers, host the app on HTTPS; browsers also permit localhost during development.

```sh
npm test
```

Tests cover RSS parsing and sanitization, unsafe XML and links, bounded requests, cache behavior and stale status, deduplication, and separate Thai/English API data.

## แหล่งข่าวและการอัปเดต / Sources and updates

The server fetches fixed AI-focused Google News RSS search queries in the selected language. Thai and English use independent in-memory caches. Categories include AI models, research, AI tools, AI coding, AI business, policy and ethics, robotics, chips and hardware, creative AI, and AI in Thailand. The general-news BBC feeds have been removed. Search feeds can include imperfect matches; category labels reflect the query that found an article and do not imply editorial verification.

The server refreshes automatically every **5 minutes** while the process runs. The first request can report `loading: true` while the initial feeds load. The API includes the last successful refresh time and each feed's status. Cached articles survive a temporary feed failure and are explicitly marked stale; a server restart clears this memory cache.

Manual refresh retries the configured sources, with a **30-second cooldown per language** to prevent repeated upstream requests. The request waits up to one second, then returns the cache with `loading: true` if collection is still running. The interface can poll the news endpoint until collection completes.

Headlines, excerpts, original publication dates, and publisher attribution come from RSS. These excerpts are **not generated by AI**. Some feeds provide no usable excerpt. Google News links can redirect to the original publisher. The interface language and preferred Google News edition follow the language menu; the app **does not translate publisher articles**. Individual articles may remain in another language if a publisher is included in the selected feed.

เมื่อเข้าถึงแหล่งข่าวไม่ได้ หน้าจอจะแสดงสถานะที่เกิดขึ้นจริง และอาจแสดง **เนื้อหาตัวอย่างที่มีป้ายกำกับชัดเจน** เพื่อสาธิตการจัดวาง ตัวอย่างเหล่านี้ไม่ใช่ข่าวสดหรือข่าวที่ตรวจสอบแล้ว API จะไม่สร้างข่าวทดแทนเอง

If feeds are unavailable, the interface reports that condition and can show explicitly labelled illustrative content to demonstrate the layout. Illustrations are not live or verified news. The API never manufactures replacement stories. The service worker caches the application shell and local assets, **not API responses or live news**; opening the shell offline does not imply fresh news is available.

## เครือข่าย / Network configuration

No API key or account is needed for the configured public RSS feeds. The Node process requires HTTPS access to:

- `news.google.com`

In a managed cloud environment, add this domain and the publisher websites whose preview images you want to resolve to the environment's outbound allowlist and save/apply the settings. A configuration draft alone does not enable connectivity. The server respects the environment's `HTTPS_PROXY`, `HTTP_PROXY`, `NO_PROXY`, and configured TLS CA trust. Do not disable certificate verification. Where a custom CA is required, configure `NODE_EXTRA_CA_CERTS` before starting Node.

### รูปภาพข่าว / Article images

Google News RSS usually omits photographs. When a real story has no RSS image, the browser now requests its preview image as the story approaches the screen. The server resolves the Google News link, reads `og:image` or `twitter:image` from the original publisher, and caches the result. The browser loads the image directly without a referrer; the server does not proxy or store image files. News headlines remain available while images load.

Image lookups accept only IDs of stories already in the current news cache. Publisher requests use HTTPS, public-address checks, publisher-host restrictions, bounded redirects, time and size limits, and a shared queue. Direct connections use checked DNS answers for the actual socket; an inherited outbound proxy remains responsible for enforcing its destination policy. Failed lookups are cached briefly to avoid repeatedly querying unavailable publishers. Queue congestion returns HTTP 503 with `Retry-After` instead of being cached as a missing photo; the browser retries once. Resolved images also appear in subsequent news responses.

Some publishers block automated access or hotlinking, omit preview images, or require a subscription. Google's link-resolution format can also change. The app now immediately shows a locally bundled photographic concept illustration while waiting for a publisher image and keeps it if the image cannot be loaded. Four AI-generated concepts (processor, developer workspace, robotics laboratory, and data center) are selected consistently by topic and story, including articles saved with the old SVG artwork. Each is visibly labelled **ภาพประกอบ AI / AI illustration**; these are not photographs of the reported events. A successfully loaded publisher photo replaces the concept image and removes its label.

The four WebP illustrations total approximately 616 KiB and are precached with the application shell, so they also display offline. They do not require access to an external image provider. The old SVGs remain a final fallback if a bundled photo is missing. Existing saved stories remain readable even when their publisher preview can no longer be resolved.

Feeds have timeouts, a 2 MiB response limit, bounded concurrency, and an explicit HTTPS hostname allowlist. User searches do not alter server fetch destinations. Bookmarks and the chosen language are stored in the browser; there is no user account or cross-device sync.

## API

- `GET /api/health`: server availability and current news status.
- `GET /api/news?lang=th`: cached stories and refresh/source status. `lang` supports `th` and `en`; optional `category` and `search` filter the results.
- `GET /api/sources?lang=th`: configured feeds, category definitions, availability, and last successful fetch timestamps.
- `GET /api/article-image/:id?lang=th`: resolve a preview image for a current story; returns `{ "imageUrl": "https://…" }` or `{ "imageUrl": null }`. Unknown IDs return 404. No caller-supplied destination URL is accepted.
- `POST /api/refresh?lang=th`: refresh the selected language's fixed feed list. Returns the news snapshot plus `refreshAccepted` and `retryAfterMs`. HTTP 202 means refresh is still running; HTTP 200 means complete or cooldown. No API key is required.

Supported category IDs: `models`, `research`, `tools`, `coding`, `business`, `policy`, `robotics`, `hardware`, `creative`, `thailand`. Use `all` or omit `category` for the combined feed.

`status` is `live` when every configured feed is healthy, `partial` when some stories are available despite feed failures, and `unavailable` when there are no cached stories. `loading` indicates a refresh in progress. Article `language` is the source language; `categories` preserves all category memberships for stories shared across feeds. Missing RSS timestamps are returned as `publishedAt: null`.

## อัปเกรดจาก WORLD BRIEF / Existing installations

The app now identifies itself as **AI BRIEF**. Previously saved articles remain available under Saved stories on the same browser and origin, including older general-news stories. Old general-news feed caches and old topic preferences are not reused for the new AI feed. Existing category illustrations remain available for older saved articles; new demo articles use distinct AI IDs to avoid collisions.

The service worker uses a new shell cache and removes previous `world-brief-shell-` caches on activation. Open the site online to receive the update. The existing hosting service name `world-brief`, repository URL, and Render plan are unchanged, so an existing deployment can keep its current public URL.

## ตรวจสอบหน้าแอพ / Browser verification

With the production server running, `python scripts/smoke.py` exercises language switching, all category filters, search, saved stories, preferences, keyboard dialogs, refresh behavior, responsive layouts, and service-worker offline reading. This optional development check requires the Python `playwright` package and Chromium at `/usr/bin/chromium`; set `CHROMIUM_PATH` and `SMOKE_URL` to override. It uses clearly separate mocked fixtures for failure cases and real HTTP requests for the installed PWA check. Screenshots and the report are written to the ignored `playwright-results/` directory. Run `python scripts/refresh-smoke.py` to verify the five-minute refresh timer, pause control, and manual-refresh polling with a simulated browser clock. Run `python scripts/image-smoke.py` for lazy preview resolution, a broken remote image, shared dialog caching, and recovery when a new image URL arrives; its image responses are deliberately mocked, so it does not establish live publisher availability.

## นำไปใช้งาน / Deployment

Deploy the complete Node application, not only the `dist/` folder: the RSS API needs the server. Run `npm ci`, `npm run build`, then `npm start` on a Node-capable host, and route HTTPS to the configured `PORT` (default 3001). The process must stay running for automatic refresh. No account, database, or API key is required. The app is a PWA that can be installed from a supported browser; it is not an App Store or Play Store package.

## เปิดให้ทุกคนใช้งานผ่าน Render

เตรียมการตั้งค่าไว้ใน `render.yaml` แล้ว โดยใช้ Web Service แผน Free และ Node.js 24:

1. เปิด [หน้าติดตั้งบน Render](https://render.com/deploy?repo=https://github.com/chalee2000/sisuwan) แล้วเข้าสู่ระบบหรือสมัครบัญชี
2. เชื่อมต่อ GitHub หากระบบร้องขอ แล้วเลือก repository `chalee2000/sisuwan`
3. ตรวจสอบว่าแผนบริการเป็น **Free** แล้วกดสร้าง/Deploy Blueprint ตามหน้าจอ
4. รอให้สถานะเป็น **Live** จากนั้นคัดลอก URL HTTPS ที่ Render แสดงเพื่อส่งให้ทุกคน

ผู้เข้าชมเปิดผ่านลิงก์ได้เลยโดยไม่ต้องติดตั้ง Node.js บนเครื่องตนเอง ไม่ต้องเปิดคอมพิวเตอร์ของผู้สร้างค้างไว้ URL จริงจะได้รับหลังสร้างบริการสำเร็จ

Render จะติดตั้ง dependencies, build หน้าเว็บ และรัน API ภายในบริการเดียวกัน แอพใช้พอร์ตที่โฮสต์กำหนดโดยอัตโนมัติ ไม่ต้องเพิ่มฐานข้อมูลหรือ API key

แผน Free อาจพักบริการเมื่อไม่มีผู้ใช้งาน ทำให้การเปิดครั้งแรกต้องรอเริ่มระบบ และข่าวจะไม่อัปเดตระหว่างที่บริการพัก หากต้องการอัปเดตตลอดเวลา ให้เลือกแผนที่รันต่อเนื่องหลังตรวจสอบราคาและเงื่อนไขของ Render เอง ไฟล์นี้เลือก Free ไว้และไม่ได้สั่งซื้อบริการแบบเสียเงิน

การเพิ่ม `render.yaml` เป็นเพียงการเตรียมติดตั้ง แอพยังไม่เผยแพร่จนกว่าจะสร้างบริการในบัญชี Render สำเร็จ
